# CoreSentia site - working rules

- The live site (the code as it currently stands) is the source of truth for design. DESIGN.md at the repo root is background reference and may lag behind it - where they conflict, the site wins. Do not restyle existing pages to match DESIGN.md.
- Never use em dashes (—) or en dashes (–) in any copy, code comments, or UI text. Use a spaced hyphen ( - ) instead. Do not touch code syntax, third-party content, URLs, or anything where the character is functional rather than typographic.

## Copy rules - public pages, anything Ramsay will paste, and chat replies
- No hedge openers: 'Most people...', 'At first...', 'It's worth noting...', 'Often...'
- No pivot phrases: 'When you do', 'That said', 'The moment...', 'The point is'
- No agreement preambles: 'Let me be precise', 'To be clear', 'Exactly right, and...'. Just say the thing.
- No three-item lists held inside dashes or commas mid-sentence. List it or cut it.
- No balanced closers: 'X, not Y', 'X, never Y', 'not just X but Y'. Say X.
- No reassurance clauses. If a sentence exists to make the reader feel better, delete it.
- Start with the verb where possible. 'Rank higher on Google', not 'You'll rank higher on Google'.
- First draft is the shortest version. Expand only if asked.
- If a sentence would look odd in a text message to a mate, rewrite it.
- Quotes: single quotes for terms and scare quotes. Double quotes only around words someone actually said. Code strings follow the file's existing style.
- Dashes: the hyphen rule above applies to chat replies too, not just copy.
